# PokéPulse search engine

The live predictor keeps bounded stochastic game search for ordinary supported matchups. Complex move callbacks use sampled native battle continuations to keep the meter responsive.

The complex path evaluates every starting move pair and applies simultaneous minimax to the resulting matrix. It first gives every pair coverage, then spends more samples on pairs that can affect the decision. Heuristic optimistic intervals stop clearly inferior rows or columns early, with a minimum exploration quota; these are scheduling approximations, not certified bounds. Competitive pairs receive continuations up to 24 turns, while initial continuations use twelve. The default maximum is 128 samples per pair.

The first native random draw is stratified when it is binary: both outcomes are sampled, including rare critical hits when that is the first draw, and their means are combined using their actual probabilities. Later draws and multiway first draws use ordinary probability-proportional sampling. This does not explicitly stratify every rare event. Estimates wait until every root pair and its strata have observations. Accuracy, critical hits and effects still execute in the native engine.

Bounded native-state caches retain root observations, continuation move choices and exact endings across slices and observations. State keys include mechanics and uncertainty. Compatible twelve-turn rollout suffix observations can seed a future root with the same state, action pair and horizon; shorter-horizon samples are not reused as twelve-turn observations. Cached choices merge equivalent continuation work; they do not substitute cached random outcomes for new samples. Near-KO endings can be enumerated exactly with a 48-node cap and at most one attempt per refinement slice, after initial sampling. Only endings in which every branch terminates are reused as exact expectations. Longer or incomplete endings still use the heuristic. Sampling does not certify the matchup percentage or provide a one-point error guarantee. Whole percentages are display precision.

The API marks sampled results with `approximate`, `certified: false`, and `score_kind: simulation-estimate`. It keeps certified bounds at 0–100 while publishing a separately usable estimate. Unread live inputs cannot become an estimate. Live nonterminal estimates stay between 1 and 99; confirmed fainted endpoints retain 0/100. The meter shows the rounded estimate with no extra marker. Ordinary exact searches retain their existing certificate behavior.

## Retained next-turn hybrid

Complex live positions now retain a next-turn layer in `analysis/retained-turn.mjs`. After the first usable reading, the worker incrementally enumerates the native chance outcomes for every starting move pair. Terminal values are exact. Equivalent nonterminal states share a retained win estimate, conditional rollout observations, and a sampled move matrix when refined. Once every pair finishes enumeration, exact transition probabilities weight the deeper estimates and simultaneous minimax backs that matrix up to the current position. Deeper estimates remain approximate.

Simple matchups still start with the fast exact adapter. If a matchup has at least four move pairs and remains unresolved after four exact passes, the live worker switches to this retained native layer. This also covers ordinary moves whose combined chance tree becomes expensive. Single-pair cases retain their existing exact path.

The optional race runs two worker threads concurrently: an exact probe and the retained hybrid. `SearchService({parallel:false})` retains the single-worker fallback above for comparisons. The server keeps that fallback as its default because initial benchmarks found extra latency and memory cost; setting `POKEPULSE_SEARCH_MODE=race` before server startup enables the race. The coordinator prefers a finished exact certificate; while exact bounds remain unresolved it chooses a usable hybrid estimate, or an informative exact estimate if the hybrid has none yet. Results from different versions are rejected. Estimates are not averaged with certificates. A completed exact result stops the competing worker's current calculation while preserving its caches for a later observation.

The exact worker probes for up to two seconds per observation, with a 20,000-state retention cap. It then parks and preserves its bounds. A new observation can reuse them and start another probe. Hybrid refinement continues independently. Each worker owns its cache; only results and cancellation tokens cross the worker boundary. The API `search_race` diagnostic reports the selected engine and each worker's status. One failed worker can leave the other available; both failing reports an error.

## Bound propagation and threshold pruning

The shared matrix solver eliminates componentwise dominated rows and columns before solving. It also recognizes domination by a uniform mixture of other actions. These rules preserve simultaneous mixed strategies; a low pure worst-case value alone does not justify removing a move. Interval dominance uses the dominating action's lower payoff vector against the other action's upper payoff vector. It therefore remains valid for every payoff matrix inside the current intervals.

Recursive exact search consults these bounds before expanding action pairs and after each chance outcome. When a row or column is proven irrelevant, it skips its remaining stochastic continuations and retains their full unknown probability mass. The persistent frontier uses the same masks, including checks for queued states whose parent actions have since been eliminated. Bound updates continue propagating through retained parents. Midpoint proof thresholds prioritize unresolved intervals that cross the current decision threshold; they do not eliminate a chance outcome on their own.

The retained next-turn layer now backs up native probability bounds, propagates changes to parents, and uses those bounds to prune turn enumeration and descendant refinement. Observation aliases share estimates, but a continuation proof is applied only to edge components with the identical full native state fingerprint. Missing and pending mass remains unknown. The displayed hybrid estimate stays separate from these internal proofs and keeps its existing uncertified API contract.

Sampling uses probability-weighted Hoeffding intervals for the bounded rollout estimator, with summable error spending across repeated checks and a per-state default budget of 0.01 divided across move pairs and two horizon epochs. A move promoted to a longer horizon keeps that horizon; its confidence statistics start afresh. Old and warm observations can remain in the display estimate, but cannot overstate evidence for the new horizon. Confidence pruning preserves an exploration floor and completed rare-event strata. Its assumptions concern independent bounded rollout observations; heuristic continuation bias and full battle prediction error are outside this statistical bound. Sampling intervals never become exact certificates.

Explicit threshold queries are available with `targetProbability` on exact search. They can stop once retained bounds prove above/below the threshold, without claiming the full numerical value is solved. `searchProbabilityThresholds` (or `thresholdSearch: true`) bisects the current bracket while sharing cached proofs and the frontier. These optional APIs are intended for focused proof experiments; the live default uses midpoint scheduling and bound pruning rather than forcing seven separate threshold queries into every pass.

On an observed turn, a mechanics key matches the reconstructed live state to a retained node. The key includes HP, PP, used moves, builds/stats, abilities/items, statuses, effect counters, field/side conditions, previous moves and uncertainty markers. Log messages, random-generator history and request bookkeeping do not define the observed position. Additional histories are included for moves/items that read them; missing histories prevent a match. A node with sampled evidence can publish its saved estimate with `warmOnly` before any new rollout. Its move matrix continues accumulating observations when refinement resumes; raising its sample target does not discard old samples. Conditional suffix observations keep their remaining-horizon counts and serve as a starting estimate, rather than being treated as completed samples for a different horizon.

The default cache retains at most 256 native states. Eviction releases snapshots, chance frontiers and sampled matrices while parent edges retain a scalar fallback. Next-turn enumeration uses roughly 15% of a normal slice and defers a pair after 512 expansion steps or a frontier over 1,024 entries. Deferred or missing mass is retained explicitly, not renormalized; incomplete turns use the sampled root fallback. Deeper child matrices receive an initial target of eight samples per pair and more work when promoted to the observed root. Initial readings defer this extra work so graph construction does not hold up first coverage.

The API reports `next_turn_exact`, completed pair counts, retained state counts, continuation samples/horizons and `reused_next_turn_estimate`. Exact next-turn probabilities do not certify the deeper win estimate. A live state that does not match retained evidence receives a fresh calculation. The benchmark series and limits are documented in [SEARCH-BENCHMARKS.md](../SEARCH-BENCHMARKS.md).

Each state expands simultaneous player/opponent move pairs. Chance branches enumerate action prevention, accuracy, damage rolls, and speed ties. Equal resulting states are merged by adding probability. State keys reuse a cached canonical field order to reduce allocation during branch merging. Damage histograms also combine duplicate and overkill rolls before expansion. The live frontier retains these states between calculation slices. The separate recursive search also supports componentwise action pruning and optional probability-tail pruning; discarded mass stays unknown rather than being renormalized.

Simultaneous action matrices use mixed-strategy minimax. Pure/single-action cases solve directly; fictitious play supplies lower/upper certificates for other matrices without claiming convergence. This represents an adversarial opponent, not Run & Bun's actual AI. Both actions are chosen before random outcomes are observed.

Leaves at depth/work limits have bounds [0,1], tightened by previously established state certificates. Mutual knockouts count as losses in the active-duel adapter. The API score is the lower bound. Bounds are conditional on implemented mechanics; they do not cover omitted mechanics or unknown team information. Heuristic evaluations guide the search but never tighten those bounds.

The live server uses a persistent worker. It publishes a 150 ms pass, then repeated 250 ms passes until the modeled interval is resolved (within one percentage point) or a new battle state replaces the search. There is no total time or pass-count limit. The horizon begins at four turns, doubles up to 128, then grows by 32; budget-limited horizons deepen at least every fourth pass. The frontier currently uses fixed 64-iteration certificate and 32-iteration estimate matrix calculations. Decision-state expansion counts have no separate cap in the worker. Passes reuse the graph and state certificates; cutoffs remain unknown and deferred leaves return when the horizon grows. Changed child bounds propagate to ancestors and can contract probabilistic cycles. HTTP/emulator polling stays on the main thread. Attempted depth is not a claim that every branch reached that depth. Unsupported continuations can remain unresolved indefinitely; more compute cannot implement missing mechanics.

## Current mechanics scope

Live searches retain one worker and its transposition table for the matchup. An observed turn becomes a new root: matching HP, PP, status, counters, and stat stages reuse the saved descendant bounds, then expand unresolved continuations. A changed model context (species, builds, field, restrictions, or actual stats) discards the table. Atomic generation checks interrupt obsolete searches and version checks prevent stale publication. Depth memo entries are capped at 80,000; state certificates are retained for the matchup so continuous refinement does not throw away established progress. Memory use can grow with distinct explored states. Leaving battle cancels the worker and releases those tables.

The default search dispatches immediately when the observed state changes. The native overlay uses established shares consistently: wins = lower bound, losses = 100 minus upper bound, unknown = upper minus lower. The combined rail leaves the unknown share empty. The API also exposes a heuristic provisional estimate, but the native rails do not treat it as established probability. The overlay polls every 120 ms and animates toward updated scores from its current position.

## Branch priorities

The live scheduler favors a promising player strategy, then explores its chance outcomes across every opponent action. Its score is path probability times a heuristic strategy influence times remaining interval width, divided by estimated resolution work. The current influence multiplier is 1 for the most promising player action and 0.02 for other actions. This is a scheduling heuristic, not an exact measurement of root sensitivity. Opponent actions receive equal scheduling weight; no strongest-counterplay priority is applied. The underlying value calculation remains minimax; NPC and human behavior models are not implemented by this scheduling change. A separate strategy-value callback allows the ranking rule to evolve independently.

Near-ending states get a mild cost preference based on estimated remaining hits. Every twentieth visited state promotes the oldest queued state, so a misleading heuristic does not permanently hide another strategy. An action is skipped only when its upper payoff against every opponent action is below an already certified minimum for the state. Opponent moves are never removed on the grounds that they are suboptimal. Rare chance outcomes keep their original probability.

Each distinct state has one heap entry, with its priority raised when a more influential path reaches it. Depth-cutoff entries return to the queue when the horizon increases. Changed child values propagate through parent links; unfinished propagation persists between slices. About 40 percent of a time slice is reserved for propagating results rather than continually expanding leaves. A single state expansion or matrix calculation can still overrun the requested budget.

Before general frontier expansion, the battle adapter enables a focused proof of a promising strategy up to four turns deep. It follows every opponent move and chance outcome for that strategy, retaining the full action matrices for reuse. Heuristics select the candidate; only enumerated results tighten its bounds. This settles the arena Wooper/Machop case even when two minimum-damage Earthquakes leave Machop alive.

Run `node --test --test-isolation=none test/priority.test.mjs test/frontier.test.mjs` for synthetic checks of deep strategy focus, inexpensive endings, rare outcomes, misleading heuristics, mixed strategies, certified elimination, and horizon growth. These tests require no ROM, save, or live emulator.

The adapter models the active pair only. It advances HP, PP, existing sleep/confusion counters and freeze/paralysis, recalculates damage/speed/accuracy after state changes, and supports explicit setup/stat-drop moves, half-HP recovery and selected status moves (listed in analysis/outlook.mjs). Unknown PP remains unlimited; missing sleep counters stay unresolved. Newly inflicted sleep uses a documented provisional duration model.

The active-matchup transitions include recoil/crash damage, survival/contact triggers, Protect/Substitute, conditional and multi-turn attacks, selected status moves, item consumption/removal, weather and other residual damage, and supported effect expiry. Missing live counters remain unresolved. Unsupported actions are retained as unknown alternatives. See analysis/MECHANICS.md for the current scope and verification limits. Full teams, switching and trainer AI remain excluded.

## Testing practice for other ROM hacks

Keep the generic search and synthetic analytic fixtures separate from ROM-specific transition adapters. No ROM/save/capture data belongs in fixtures. Validate transition probability sums, state identity (including PP/status/counters), simultaneous decisions, and probability mass preservation before performance tuning. Compare small games against exhaustive enumeration and hand-derived answers. Test priority, setup, wake-up trajectories, terminal endpoints, cutoffs, matrix mixed strategies, branch merging, worker cancellation and API/UI propagation independently.

The status matrix uses level-5 fixtures to resolve quickly and deterministically. Live-size snapshots retain bounded-budget regression tests and may legitimately return broad intervals. Three minimum-damage hits need not preserve the prior forecast if higher rolls were possible; use controlled deterministic rolls for monotonicity assertions, and compare identical wake-up states separately.

Run with the bundled node.exe:
- node --test test/*.test.mjs
- node test-ground/api-smoke.mjs (or --package)
- node test-ground/benchmark.mjs
- powershell.exe -NoProfile -ExecutionPolicy Bypass -File test-ground/overlay-controls.ps1

The native overlay renders one per-pixel-alpha layered window. Background and foreground elements have separate opacity controls; the meter retains stoplight colors and the track retains an opaque black border.

The overlay uses paired win/loss rails. The three-dot menu's Show submenu selects Wins and losses, Wins only, or Losses only; overlay-settings.json preserves the choice. Loss bounds reverse the win bounds: [100-upper, 100-lower]. Solid rails continuously follow the provisional display estimate; the tracks retain black outlines regardless of fill opacity. The headline shows the win outlook except in Losses only mode, which shows its complement. As elsewhere in the model, draws count as half a win.

## Held items

Held items already supplied calculator damage and Speed modifiers. The future tree now retains each holder's current item and chosen Choice move in its state key. Consumed berries and Focus Sash disappear from future calculations; item changes also invalidate damage memo entries. Supported effects include Oran/Sitrus and status-curing berries, Focus Sash between hits, Leftovers/Black Sludge, Life Orb recoil, Rocky Helmet contact recoil, Choice move locks, Flame/Toxic Orbs, Wide Lens, Bright Powder and Lax Incense. Burn and poison damage progress at turn boundaries so orb effects persist into future turns.

Resistance berries, selected reactive items and item theft/removal now change future states. Miscellaneous unsupported triggers and ROM-specific timings remain incomplete. Existing Choice locks require an adapter-provided locked_move; otherwise the lock starts with the first simulated action. Existing toxic poison without a known counter leaves the relevant residual continuation unresolved. Preserve these limitations when interpreting bounds. Synthetic item tests are in test/held-items.test.mjs; do not substitute personal save files for fixtures.

Move secondaries now use bundled Showdown metadata for the Generation 8 catalogue plus all eight Run & Bun chance edits. They branch status, stat changes, flinch, confusion, PP drain and terrain effects, including callback effects omitted by Showdown's JSON export. Sheer Force, Serene Grace, Shield Dust, status immunity and stat-change abilities are accounted for. Re-estimation cache keys include confusion, Focus Energy and terrain; changed states recalculate accuracy, critical chance, damage and speed. Focus Energy is a supported setup action. Eerie Spell is unresolved if the last used move or its PP is unknown.

Multi-hit attacks use independent per-hit critical and damage rolls and Generation 8 hit-count probabilities (2/3 hits: 35% each; 4/5 hits: 15% each). Skill Link forces the maximum count. Triple Kick/Axel use increasing per-hit power and stop on an accuracy failure unless Skill Link applies. Sash, healing/status berries, drain and Rocky Helmet resolve between hits; equivalent states merge after each hit. Berry flavor compares against the nature's lowered stat and branches confusion durations. Confusion self-hit damage branches over all sixteen damage rolls. See test/run-bun-effects.test.mjs for analytic outcome and probability-mass checks.

The live worker uses a persistent state graph and a probability-prioritized expansion frontier. Each state retains its transition matrix and probability-weighted child edges; equivalent child states merge. Interval backups propagate terminal outcomes to ancestors and tighten cycles across passes. Unexpanded states keep [0,1] bounds. Compatible new observations reroot into the retained graph. The recursive search remains available for bounded diagnostic replay and reference tests. Frontier tests cover analytic stochastic values, mixed strategies, rerooting and unresolved cycles.

Unfinished frontier nodes now carry a heuristic estimate based on expected attacking damage and turns needed to KO, with rough sleep/paralysis/freeze adjustments. Transition probabilities weight these estimates, and the action matrix backs them up to the root. Real expanded outcomes replace guesses. The estimate is clamped to independently computed bounds and never used to certify or prune branches. This is a provisional evaluation, not a calibrated probability. Already solved simple positions can still finish on the first pass; no artificial waiting is inserted.

## Run & Bun 1.07 turn boundaries

The live adapter reads gBattleMainFunc, the completed-turn counter and current queued-action index directly from existing RAM captures. Exact fingerprinted callback addresses are documented in run-bun/reference/adapter-profile.json. Selection and action callbacks were disassembled and observed across live gameplay; the end-turn callback was identified in ROM code. Unknown callbacks are transitions, never assumed to be fresh turns.

Only selection commits a new nonterminal search root. During attack animations and end-turn effects, the existing search continues from the last decision state; its results are marked pending and retain their based_on_state_id. A confirmed active-battler faint can resolve immediately. No fixed settling timeout is used. This prevents granting another action after the first hit of a turn. Pending values describe the preceding decision tree; conditioning probabilities on individual queued actions is not implemented. For other ROM hacks, locate and verify their own callbacks; do not reuse these addresses.

Struggle is the sole action when every real move is unusable, including exhausted PP or a depleted Choice-locked move. Unsupported but usable moves remain unknown rather than forcing Struggle. Damage uses the existing calculator; Struggle consumes no PP, bypasses accuracy checks, and applies generation-specific recoil (Run & Bun uses the Generation 8 rule). Mutual knockouts count as losses in this active-duel model. Adapter-only tests must supply a Struggle damage row for action index -1. ROM-specific recoil timing remains to be live verified.
